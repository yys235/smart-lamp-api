## 1. 项目概述

### 1.1 项目背景

Smart Lamp API 是一个智能灯具控制系统的后端服务，用于管理和控制通过网关连接的智能灯泡设备。该服务从原 Java Spring Boot 项目迁移至 Python FastAPI 架构。

### 1.2 项目目标

- 提供统一的 REST API 接口控制智能灯泡
- 支持网关自动发现和设备管理
- 实现事件驱动的设备状态同步
- 提供操作日志和历史记录功能

### 1.3 系统范围

| 包含 | 不包含 |
|------|--------|
| 灯泡开关控制 | 用户认证系统 |
| RGB 颜色调节 | 多租户支持 |
| 亮度控制 | 移动端应用 |
| 网关设备发现 | 第三方系统集成 |
| 状态查询与历史 | 实时 WebSocket 推送 |

## 2. 功能需求

### 2.1 功能清单

| ID | 功能名称 | 描述 | 优先级 |
|----|----------|------|--------|
| FR-01 | 网关自动发现 | 通过 UDP 广播自动发现局域网内网关设备 | P0 |
| FR-02 | 获取灯泡列表 | 掷取所有已连接灯泡的当前状态 | P0 |
| FR-03 | 获取单个灯泡 | 根据 device_id 获取指定灯泡状态 | P0 |
| FR-04 | 开启单个灯泡 | 控制指定灯泡开启，支持 RGB 和亮度设置 | P0 |
| FR-05 | 关闭单个灯泡 | 控制指定灯泡关闭 | P0 |
| FR-06 | 开启全部灯泡 | 同时开启所有灯泡 | P0 |
| FR-07 | 关闭全部灯泡 | 同时关闭所有灯泡 | P0 |
| FR-08 | 网关状态查询 | 获取网关连接状态和统计信息 | P0 |
| FR-09 | 健康检查 | 服务健康状态检查端点 | P0 |
| FR-10 | 操作日志查询 | 查询历史操作记录 | P1 |
| FR-11 | 事件通知 | 设备状态变更事件通知 | P1 |

### 2.2 功能详细描述

#### FR-01: 网关自动发现

系统启动时自动监听 UDP 端口 41328，接收网关广播消息并解析网关信息。

**输入**: 无
**输出**: 网关 IP 地址、网关 ID
**触发条件**: 服务启动或调用主动发现接口

#### FR-02: 获取灯泡列表

返回所有已连接灯泡的当前状态，包括 RGB 颜色值和亮度。

**输入**: API Key (认证)
**输出**: 灯泡数组，每个包含 device_id, name, red, green, blue, intensity

#### FR-03: 获取单个灯泡

根据指定的 device_id 返回单个灯泡的状态。

**输入**:
- device_id (int, >=1): 设备唯一标识

**输出**: 单个灯泡状态或 404 错误

#### FR-04: 开启单个灯泡

控制指定灯泡开启，并设置 RGB 颜色和亮度。

**输入**:
- device_id (int, >=1): 设备唯一标识
- red (int, 0-255): 红色值，默认 255
- green (int, 0-255): 绿色值，默认 255
- blue (int, 0-255): 蓝色值，默认 255
- intensity (int, 0-255): 亮度，默认 255

**输出**: 更新后的灯泡状态

#### FR-05: 关闭单个灯泡

将指定灯泡的亮度设为 0（关闭）。

**输入**:
- device_id (int, >=1): 设备唯一标识

**输出**: 更新后的灯泡状态

#### FR-06/FR-07: 批量控制

同时控制所有灯泡的开启或关闭。

**输入**: (开启时) RGB 和亮度参数
**输出**: 所有灯泡的更新状态数组

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 要求 |
|------|------|
| API 响应时间 | < 500ms (P95) |
| 网关发现时间 | < 30 秒 |
| 并发请求数 | 支持 50+ 并发连接 |
| TCP 超时时间 | 5 秒 |

### 3.2 可用性需求

| 指标 | 要求 |
|------|------|
| 服务可用率 | 99%+ |
| 网关断线重连 | 自动重连机制 |
| 控制失败重试 | 自动重试 1 次 |

### 3.3 安全需求

| 需求 | 描述 |
|------|------|
| API 认证 | 支持 API Key 认证 |
| 输入验证 | 所有参数必须验证范围和类型 |
| 错误处理 | 不暴露敏感系统信息 |

### 3.4 可维护性需求

| 需求 | 描述 |
|------|------|
| 日志记录 | 结构化日志，支持 log rotation |
| 配置管理 | 环境变量配置，支持 .env 文件 |

## 4. 约束条件

### 4.1 技术约束

- **框架**: FastAPI
- **Python 版本**: 3.10+
- **数据库**: SQLite (开发) / 可扩展其他数据库
- **协议**: Ledo 自定义二进制协议

### 4.2 硬件约束

- **UDP 端口**: 41328 (固定，不可配置)
- **TCP 端口**: 41330 (固定，不可配置)
- **网络**: 与网关设备在同一局域网

### 4.3 兼容性约束

- 需兼容原 Java 版本控制的网关设备
- 保持相同的 Ledo 协议格式

## 5. 用例描述

### 5.1 开启灯泡用例

**用例名称**: 开启指定灯泡

**参与者**:
- 主参与者: API 客户端
- 系统: Smart Lamp API
- 外部系统: 网关设备

**前置条件**:
1. 服务已启动
2. 网关已发现并连接
3. 指定的灯泡设备存在

**主流程**:
1. 客户端发送 POST 请求到 `/api/v1/lamps/{device_id}/on`
2. 系统验证 API Key
3. 系统验证 device_id 参数
4. 系统获取当前灯泡列表
5. 系统更新目标灯泡的 RGB 和 intensity 值
6. 系统通过 TCP 发送更新命令到网关
7. 网关执行控制并响应
8. 系统等待 0.5 秒后验证状态
9. 系统返回更新后的灯泡状态

**备选流程**:
- 4a. 网关未连接: 返回 500 错误
- 6a. TCP 通信超时: 返回 500 错误并记录日志
- 8a. 状态验证失败: 自动重试一次

**后置条件**: 灯泡已开启并设置指定颜色和亮度

### 5.2 网关发现用例

**用例名称**: 自动发现网关设备

**前置条件**: 服务启动

**主流程**:
1. UDP 客户端启动，绑定端口 41328
2. 网关发送 UDP 广播消息
3. 系统接收并解析广播包
4. 系统提取 gateway_id 和 IP 地址
5. 系统触发 gateway_connected 事件
6. 系统通过 TCP 获取灯泡列表

**后置条件**: 网关已连接，灯泡列表已加载
